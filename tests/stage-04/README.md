# Stage04：SPIM 回归测试

在项目根目录运行：

```sh
make test-04
# If SPIM is not on PATH:
make test-04 SPIM=/path/to/spim
```

`make test-04` 分别用项目的 `./cc` 和 `./parser` 生成 `.s` 文件，再通过 `spim -file` 执行。两个入口都必须通过，以覆盖评测使用不同可执行文件名的情况。`SPIM` 可指定可执行文件路径，无须修改 Makefile。

| 用例            | 检查内容                                                                   |
| --------------- | -------------------------------------------------------------------------- |
| `fibonacci`     | 从标准输入读入项数，通过循环逐行输出 Fibonacci 数列                        |
| `recursion`     | 递归基例，以及同一表达式中的两次递归调用和返回值                           |
| `arrays`        | 局部整数数组、动态下标读写、常量下标覆盖、负数输出                         |
| `calls-control` | 六参数的顺序、嵌套调用、循环、分支与逻辑短路（不能调用带输出副作用的函数） |

每个 `cases/*.cmm` 对应一个 `.out`，可选的 `.in` 提供标准输入；没有 `.in` 则使用空输入。runner 只剥离已知的 SPIM 启动信息及 `Enter an integer:` 读入提示，然后用 `diff -u` 比较完整输出，不截取数字行。编译失败、缺失或空汇编、SPIM 非零退出、SPIM 标准错误非空，以及标准输出不符（包括混入的模拟器错误）都会导致用例失败。runner 会报告每个用例及汇总，任一失败时返回非零状态；临时汇编和日志会自动清理。
