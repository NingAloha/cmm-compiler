# 词法分析器：把字符流转换为带信息的 token

对应源码：[src/frontend/lexer.l](../../src/frontend/lexer.l)。本文件说明的是当前全功能版本：基础词法之外，还实现了八/十六进制整数、指数浮点数和两类注释。

## 1. 在整个程序中的位置

程序入口在 `main.c` 中把输入文件赋给 Flex 提供的 `yyin`，然后调用 `yyparse()`。Bison 在需要下一个 token 时调用 `yylex()`；Flex 生成的 `yylex()` 根据本文件的规则读取字符，并返回 `INT`、`ID`、`LP` 等 token。

```
源文件 → yyin → Flex/yylex() → token + yylval.node → Bison/yyparse()
```

这里不只是“返回 token 类型”：每一个 token 同时通过 `yylval.node` 携带一个已经创建好的 `TreeNode`。因此，后续语法动作无需重新保存原始词素和行号。

## 2. Flex 配置与公共辅助函数

文件开头的配置有三个关键点：

- `%option yylineno`：Flex 在每读到换行后自动维护 `yylineno`；所有 token 和错误均使用该行号。
- `%option noyywrap`：文件结束时不要求自定义 `yywrap()`。
- `%x COMMENT`：声明独占的 `COMMENT` 开始条件，用于扫描块注释。

`make_token(token, name, text)` 是所有普通 token 的统一出口：它调用 `tree_new(name, text, yylineno)`，把树结点放进 `yylval.node`，再返回 Bison 所需的 token 编号。关键字 `int`/`float` 保存其文字；其他关键字与标点通常传入空字符串，普通非终结符则由 Bison 创建。

数值 token 有专门的转换函数：

- `make_int_token()` 用 `strtoul(text, NULL, 0)` 转换。第三个参数为 `0` 会让 C 库按前缀选择十进制、八进制或十六进制，随后以十进制文字存入 `INT` 结点。
- `make_float_token()` 用 `strtof()` 转为 `float`，再用 `%f` 保存十进制显示值。这也是为什么例如 `1.05e-4` 在语法树中显示为 `0.000105`。

## 3. 标识符、关键字与运算符

标识符规则是 `ID [A-Za-z_][A-Za-z0-9_]*`，即首字符不能是数字。关键字规则放在 `ID` 规则之前，因此 `int` 会被识别为 `TYPE`，不会落入 `ID`；而 `integer` 会因最长匹配规则整体成为 `ID`。

多字符运算符（如 `>=`、`==`、`&&`）也单独定义。Flex 首先选择能匹配**最长文本**的规则，所以 `>=` 不会拆成 `>` 和 `=`；在相同长度的候选规则之间，才由规则在文件中的先后顺序决定。

空白符和换行不返回 token。换行单独匹配，是为了让读取行为直观；实际行号递增由 `yylineno` 自动完成。

## 4. 数字规则与“合法规则优先”

### 4.1 合法数字

规则分为以下几类：

| 类别 | 规则要点 | 示例 |
| --- | --- | --- |
| 十进制整数 | `DEC_INT` | `0`、`42` |
| 八进制整数 | `0` 开头，后续仅为 `0`–`7` | `0123` |
| 十六进制整数 | `0x`/`0X` 开头，后续为十六进制数字 | `0x3F` |
| 普通浮点数 | 小数点两侧都有数字 | `0.7`、`12.43` |
| 指数浮点数 | 含小数点的基数 + `e`/`E` + 可选正负号和指数数字 | `1.05e-4`、`43.e-4`、`.5E03` |

普通浮点数使用 `PLAIN_FRACTION`；指数形式的基数使用更宽松的 `EXP_BASE`，所以只有指数形式允许 `43.` 或 `.5`。纯 `1e3` 不符合“基数有小数点”的要求。

### 4.2 非法数字为什么要专门匹配

`BAD_OCT`、`BAD_HEX`、`BAD_EXPONENT`、`BAD_NO_DOT_EXP`、`BAD_LEADING_DOT` 等规则把一个错误数字整体吃掉，并调用相应的 A 类错误函数。例如 `09` 不会被拆成 `INT(0)` 与 `INT(9)`，`0x3G` 不会被拆成 `INT(0)` 与 `ID(x3G)`。

这有两个好处：错误行号与错误文本更准确；错误类型是题目要求的词法错误 A，而不是由 token 拆分造成的语法错误 B。

合法规则排在相应的非法规则前面也很重要。例如合法 `0x3F` 同时满足宽泛的 `BAD_HEX`，但两者匹配长度相同，Flex 选择先写的 `HEX_INT`，所以它仍然是合法整数。

## 5. 注释状态机

单行注释规则 `"//".*` 直接丢弃到行末的内容；换行仍会被后面的换行规则读取和计数。

块注释使用 `COMMENT` 状态：

```
INITIAL --遇到 /*--> COMMENT --遇到最早的 */--> INITIAL
```

进入状态时，`comment_start_line` 记录起始行。处于 `COMMENT` 时，普通字符和换行都被忽略；若先到达文件末尾，则报告 `Unterminated comment` 的 A 类错误，并指向起始行。

注意：在 `COMMENT` 状态下，内部的 `/*` 没有特殊规则，因此它只是普通内容；最先遇到的 `*/` 就结束注释。这正是“不支持嵌套块注释”的含义。

## 6. 词法错误如何影响最终输出

未知字符落入最后的 `.` 规则，调用 `report_mysterious_character()`。所有词法错误函数都会将全局 `lexical_error` 置为 `1` 并打印：

```text
Error type A at Line <line>: <description>.
```

错误规则不返回一个可供语法分析的普通 token。即使 Bison 随后还能继续恢复，`main.c` 也会因为 `lexical_error` 为真而不打印语法树，并以非零状态码退出。这保证了“有词法或语法错误时不输出语法树”的提交要求。
