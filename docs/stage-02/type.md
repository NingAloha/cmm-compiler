# 类型系统：统一表示 C-- 的值、复合类型和错误类型

对应源码：[src/semantic/type.h](../../src/semantic/type.h) 与 [src/semantic/type.c](../../src/semantic/type.c)。语义分析不直接用字符串表示类型，而是让每个表达式分析结果返回 `Type *`；声明、赋值、运算和函数调用都基于这一对象比较类型。

## 1. 类型与域的表示

`Type` 是带标签的联合体，`kind` 决定联合体中哪一部分有效：

| `TypeKind` | 保存的信息 | 用途 |
| --- | --- | --- |
| `TYPE_INT`、`TYPE_FLOAT` | 无额外字段 | 两种基础数值类型 |
| `TYPE_ARRAY` | 元素类型、当前维长度 | 一维或多维数组 |
| `TYPE_STRUCT` | 标签名、成员链表 | 具名或匿名结构体 |
| `TYPE_FUNCTION` | 返回类型、形参链表 | 函数定义与调用检查 |
| `TYPE_ERROR` | 无额外字段 | 抑制后续连锁错误 |

`Field` 是单链表结点，保存名称、类型、定义行号和 `next`。同一个结构既复用为结构体成员表，也复用为函数形参表，因此 `field_find()`、`field_append()` 等基本操作不用重复实现。

## 2. 共享基础类型与构造函数

`type_int()`、`type_float()` 和 `type_error()` 分别返回静态共享对象。基础类型不需要为每个变量单独分配内存，且调用方可稳定地获得同一种类型的描述符。

数组、结构体和函数通过 `type_new_array()`、`type_new_structure()`、`type_new_function()` 动态创建。数组结点只保存一层维度；例如 `int a[2][3]` 会构造“长度 2 的数组，其元素是长度 3 的数组，其元素为 `int`”的嵌套结构。结构体标签和域名称均复制字符串，避免持有词法分析缓冲区中的临时指针。

## 3. 类型等价规则

`type_equal(left, right)` 实现本实验的名等价规则：

- `int` 只等价于 `int`，`float` 只等价于 `float`；
- 数组递归比较元素类型，**不比较**每一维的具体长度，因此 `int a[10][2]` 与 `int b[5][3]` 等价；
- 结构体按 `Type *` 指针身份比较，两个独立定义即使成员相同也不等价；
- 函数比较返回类型及形参类型序列，不比较形参名称；
- 任一侧为 `TYPE_ERROR` 时返回等价，用来保留已发现的根本错误，而不为同一个问题继续输出类型错误。

`type_is_numeric()` 只对 `int` 和 `float` 返回真，供算术运算和一元负号检查使用；逻辑运算、关系运算以及 `if`/`while` 条件则由语义遍历额外要求 `int`。

## 4. 与语义遍历的边界

类型模块只负责创建、查询和比较，不打印错误，也不保存符号的作用域信息。`semantic.c` 决定某个 AST 结点应当使用哪种类型、何时报告错误 5/7/8/9/10/12/13/14 等；`symbol.c` 负责将类型关联到变量、函数和结构体名称。这样的分层使类型单元测试无需依赖 Flex、Bison 或语法树。
