# 语义分析：遍历 AST 并报告类型错误

对应源码：[src/semantic/semantic.h](../../src/semantic/semantic.h) 与 [src/semantic/semantic.c](../../src/semantic/semantic.c)。默认运行 `./parser source.cmm` 时，词法和语法分析成功后会调用 `semantic_analyze()`；无语义错误不输出，出错时通过标准输出打印 `Error type N at Line L: message.`。传入 `--tree` 则保留实验一的语法树输出模式。

## 1. 分析上下文与 AST 辅助函数

`SemanticContext` 集中保存符号表、当前函数的返回类型和已报告错误数。`semantic_analyze()` 创建该上下文，执行 `Program → ExtDefList` 的递归遍历，最后清空符号表并返回错误计数。

语法树采用“第一个孩子—下一个兄弟”结构，因此语义模块提供：

- `child_at(node, index)`：沿 `next_sibling` 取第 `index` 个孩子；
- `node_is(node, name)`：空指针安全的结点名称比较；
- `find_child(node, name)`：查找直接孩子中的指定非终结符；
- `report_error(...)`：统一检查错误编号、输出错误格式并累计错误数。

这些辅助函数把 AST 的指针细节隔离在少量函数中，使后续分析函数主要按文法结点组织。

## 2. 声明、函数和结构体

顶层 `ExtDef` 分为变量声明、仅含类型的声明和函数定义。`VarDec` 递归构造数组类型；`var_dec_identifier()` 沿数组声明的内层 `VarDec` 找到最终 `ID`。变量经 `declare_variable()` 插入符号表，重复定义报告错误 3。

函数分析先构造函数类型并插入函数符号，再分析函数体，所以函数可以递归调用。`VarList` 被转换为形参 `Field` 链表，进入函数作用域后逐个插入；重复形参会被视为重复变量。`current_return_type` 在分析函数体期间保存返回类型，`return` 语句据此检查错误 8。

结构体定义建立 `TYPE_STRUCT` 和域表：标签重复报告错误 16，引用未定义标签报告错误 17，重复字段或字段初始化器报告错误 15。成员访问先确认左侧为结构体（错误 13），再在域表中查找字段（错误 14）。

## 3. 表达式规则与错误分类

`analyze_exp()` 返回表达式的 `Type *`。关键检查如下：

| 场景 | 错误类型 |
| --- | --- |
| 标识符未定义、函数未定义 | 1、2 |
| 重复变量、重复函数 | 3、4 |
| 赋值两侧不等价、左侧不是左值 | 5、6 |
| 算术/关系/逻辑运算或条件类型不合法 | 7 |
| 返回值不匹配 | 8 |
| 实参数量或类型不匹配 | 9 |
| 非数组下标、下标不是 `int` | 10、12 |
| 普通变量作为函数调用 | 11 |
| 非结构体成员访问、成员不存在 | 13、14 |
| 结构体字段或标签定义错误、未定义结构体 | 15、16、17 |

赋值前会先递归分析左右表达式，再用 `exp_is_lvalue()` 接受标识符、数组元素和结构体成员三类左值。函数调用借助 `arguments_match()` 按形参链表递归比较实参；数组访问返回数组元素类型，因此多维数组可连续下标访问。

## 4. 错误传播和运行边界

当子表达式已经返回 `TYPE_ERROR` 时，父表达式直接传播它，而不再打印由该错误派生的类型不匹配。这使一个未定义变量不会同时制造大量错误 5 或 7。

语义分析只在 `yyparse()` 成功、且没有词法或语法错误时运行；因此 A/B 类错误不会与语义错误混合输出。程序对已打开的输入文件完成处理后正常返回 `0`，评测器应以标准输出中的错误类型和行号判定结果。
